## Repository Overview

Personal dotfiles for two Macs (a work laptop and a personal machine),
**mid-migration from GNU Stow to Nix / home-manager (flakes)**.

Current state is **hybrid**:
- **home-manager** manages `zsh`, `git`, and `ssh` (the things that diverge per machine).
- **GNU Stow** still manages `ghostty`, `karabiner`, and `streamdeck`.

Both machines are served from one flake via named configurations:
- `work-laptop` — this machine; carries **both** personal (default) and work
  git identities.
- `personal` — personal machine; personal identity only.

## Nix / home-manager (primary going forward)

### Structure
```
flake.nix                     # inputs (nixpkgs-unstable, home-manager); outputs homeConfigurations.{work-laptop,personal}
home/
  common.nix                  # shared: home.packages, starship.toml symlink, imports modules
  hosts/work-laptop.nix       # work email (includeIf ~/code/commerce/), gcw/gcwm, both SSH keys + github-bc
  hosts/personal.nix          # personal SSH key only
modules/
  zsh.nix                     # aliases, history, plugins, PATH, profileExtra (brew shellenv + nvm), gone()
  git.nix                     # personal identity + base config
```

### Commands
```bash
# Apply on THIS machine (work laptop)
home-manager switch --flake ~/Dotfiles#work-laptop

# Apply on the personal machine
home-manager switch --flake ~/Dotfiles#personal

# Dry build (evaluate/compile without activating) — always do this first
nix build ~/Dotfiles#homeConfigurations.work-laptop.activationPackage --no-link

# Roll back a bad switch
home-manager generations
home-manager switch --rollback
```
Flakes only see git-tracked files — `git add` new files before building.

### Per-machine identity (work laptop)
- Git default = personal (`102450568+chris-nowicki@users.noreply.github.com`).
- Work email (`chris.nowicki@bigcommerce.com`) is applied under `~/code/commerce/`
  via `programs.git.includes` (`condition = "gitdir:~/code/commerce/"`).
- SSH keys (NEVER managed by Nix — secrets): `id_ed25519_personal` (personal,
  `github.com`) and `id_ed25519_bc` (work, `github-bc` host alias). The personal
  machine uses a single default-named `id_ed25519`.
- `~/.ssh/config` is generated by `programs.ssh` with `enableDefaultConfig =
  false` and preserves Conductor's `Include conductor_config`.

### Node
Node is intentionally left to **nvm** (not pinned in Nix). `brew shellenv` and
nvm are re-created in `.zprofile` via `programs.zsh.profileExtra`.

### Making changes
- New CLI tool → `home.packages` in `home/common.nix` (or a module).
- Config that differs per machine → the relevant `home/hosts/*.nix`.
- Static config file kept verbatim → `xdg.configFile."x".source = ../pkg/...`
  (a "dumb symlink", e.g. `starship.toml`).

## GNU Stow (legacy — being retired)

Still manages the not-yet-migrated packages. Each top-level dir (except `.git`,
`.claude`, and the Nix dirs above) mirrors the home directory structure and is
symlinked with Stow. Prereq: `brew install stow`.

```bash
stow [package]      # link a package (ghostty, karabiner, streamdeck)
stow -D [package]   # unlink (used when migrating a package to Nix)
stow -R [package]   # re-stow after directory-structure changes
```

Example: `ghostty/.config/ghostty/config` → `~/.config/ghostty/config`.

The `zsh`, `git`, and `starship` package dirs remain in the repo as a **fallback
during the transition** (their symlinks were removed with `stow -D`). Re-running
`stow zsh git starship` restores the pre-Nix setup.

## Karabiner Keyboard Remapping

The `karabiner` package (still Stow-managed) remaps Caps Lock to a Hyper Key
(Ctrl+Shift+Cmd+Option):
- Pressing alone still sends Caps Lock (preserves toggle functionality).
- Holding creates the modifier combination for custom shortcuts.
- Complex modifications live in `karabiner.json` and
  `assets/complex_modifications/`.
